# Milestone v1.0: Metrics Layer

**Status:** SHIPPED 2026-01-29
**Phases:** 1-5
**Total Plans:** 7

## Overview

This milestone hardened the metrics layer by moving derived calculations into SQL views, adding data quality checks, creating aggregated serving views for dashboards, enabling eFish reconciliation, and updating the dashboard to consume the new views. All work built on the existing `quota_remaining` view as the single source of truth.

## Milestone Summary

**Key Decisions:**

- Use 'ok' not 'healthy' for risk_level to match existing Python RISK_COLORS
- Check allocation_lbs = 0 FIRST in CASE to prevent division errors
- Use NOT EXISTS pattern for species validation (clearer than LEFT JOIN)
- Use FULL OUTER JOIN for reconciliation (captures bi-directional discrepancies)
- Set 100 lbs as investigation threshold (balance noise vs material discrepancies)
- Use COUNT(*) FILTER for conditional aggregation (PostgreSQL 9.4+ syntax)
- Rename remaining_pct to pct_remaining for downstream compatibility

**Issues Resolved:**

- Python/SQL calculation drift risk eliminated
- Data quality issues now detectable via SQL
- Reconciliation with eFish now possible

**Tech Debt:**

- Serving views (kpi_daily_by_species, kpi_coop_summary) not yet consumed by UI
- reconciliation_variance view not yet consumed by UI
- Views are non-materialized (can materialize later if performance requires)
